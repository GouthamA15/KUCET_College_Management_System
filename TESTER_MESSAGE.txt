FEATURE TESTING: Bonafide 'Pay Once, Free for 4 Years' & Payment Fraud Detection

1. BONAFIDE FEE WAIVER & LIMIT LOGIC
---------------------------
- Initial Request: Log in as a student who hasn't requested a Bonafide yet. Select "Bonafide Certificate".
  * Expected: Fee = ₹100. QR code and UTR input visible.
- Clerk Approval: Submit the request. Log in as a Clerk (Admission role) and APPROVE that request.
- Subsequent Request (Same Year): Log in as the same student and try to request another Bonafide for the SAME academic year.
  * Expected: API should return error: "You have already received a Bonafide Certificate for the current academic year... Only one is allowed per year."
- Max Limit Check (Regular): Use a regular student (no 'L' in roll no). Simulate having 4 approved Bonafides (using Time Machine across 4 different academic years).
  * Expected: 5th request should return error: "You have reached the maximum limit of 4 Bonafide Certificates..."
- Max Limit Check (Lateral): Use a lateral entry student ('L' at end of roll no). Simulate having 3 approved Bonafides.
  * Expected: 4th request should return error: "You have reached the maximum limit of 3 Bonafide Certificates..."
- Free Logic: For the 2nd, 3rd, or 4th valid yearly request, the fee should be ₹0.
- Reject Scenario: If a Bonafide was previously REJECTED, it does NOT count towards the limit.

2. PAYMENT FRAUD DETECTION (Screenshot Fingerprinting)
------------------------------------------------------
- Scenario: Two different students using the same payment screenshot.
- Step 1: Student A submits a request with Payment Screenshot 'X'.
- Step 2: Student B submits a different request but uploads the SAME Payment Screenshot 'X'.
- Step 3: Log in as a Clerk and check the Certificate Request Dashboard.
  * Expected: Student B's request should show a "Fraud Detected" or "Flagged" alert.
  * Expected: The dashboard should show details about the conflict (e.g., "Conflict with Student A - Roll No: XXX").

3. TRANSACTION ID CONFLICT
--------------------------
- Step 1: Student A submits a request with UTR '123456'.
- Step 2: Student B submits a request with the SAME UTR '123456'.
- Step 3: Check Clerk Dashboard.
  * Expected: The request should be flagged for Transaction ID conflict.

Note: Fraud detection logic is automatically bypassed for "Free" Bonafide requests since no screenshot is uploaded.
